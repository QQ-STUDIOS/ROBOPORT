# Grader verification boundaries

The runtime verifies two blinded model assessments and resolves their citations against the exact artifact context. The model selects source/pointer pairs from a bounded inventory of existing JSON paths. Large artifacts retain container references; omitted step context cannot be cited by an assessment. Empty strings are valid evidence for assertions about emptiness.

Scalar string constants must be JSON quoted, except the runtime status enums ok and failed and the explicit phrase an empty string. Ambiguous predicates such as is empty or is correct remain unsupported model judgments. A conservative runtime assertion grammar independently checks scalar equality (`is` or `==`), ledger sums and counts, negative transaction counts, booleans, and extraction hash equality. Supported report fields are direct final-output or summary fields. Ledger operands must come from the unique successful data_engineering step identified in the plan. Arithmetic uses bounded Decimal values; duplicate JSON keys, nonfinite numbers, ambiguous operands, and missing evidence fail closed. Artifact instructions never define predicates or expected values.

Each checked result records `deterministic_check` and retains both original model assessments, including any wrong findings. `verification.deterministic_coverage` is the number of assertions checked by runtime rules. A recognized assertion with unavailable evidence is INCONCLUSIVE. Provider, schema, and invalid-reference failures still require review and cannot retain provisional passes.

Unsupported prose continues to use blinded model consensus. Agreement and valid references do not guarantee semantic correctness: these results are model judgments, not independently proven facts. Use supported explicit factual assertions or an independent artifact audit for acceptance-critical quantitative claims. The checks establish consistency with recorded extraction evidence; they do not authenticate an arbitrary external dataset or guarantee that all prose expectations are true.

Planner execution flags are copied from the registered agent metadata after generation. They are not model decisions. DataOps plans additionally require the ordered CleanedDataset and DataReport contracts.

The explicit grammar also accepts complete paraphrases for arithmetic sum, extracted-list length, and counting every extracted transaction below zero, plus `SUM(extracted transaction amounts)`, `COUNT(extracted transactions)`, and `COUNT_NEGATIVE(extracted transaction amounts)`. Fixed field aliases are `total` -> `total_amount`, `row count` -> `row_count`, `refund count` -> `refund_count`, and `source hash` -> `source_sha256`. It accepts explicit JSON boolean predicates, zero-character string predicates, and extraction source-hash identity. These full productions may end in a period; general scalar syntax retains its existing strict literal rules. Unsupported or qualified prose continues through consensus.

The persisted grading schema accepts both the legacy `blinded_consensus` method and `deterministic_checks_and_blinded_consensus`. The current method requires nonnegative integer deterministic coverage. Resolved citations require a nonempty source name, a syntactically valid JSON pointer, and a string quote (including an empty quote). Shape validation does not prove pointer resolution or that coverage equals the actual checked-row count; runtime validation and the recorded checks provide those guarantees.

Explicit `summary` subjects bind only to `final_output.summary`, across aggregate, boolean, scalar, and zero-character forms. A root field cannot supply missing summary evidence or override a summary value. Existing canonical `The reported IDENTIFIER equals the ...` productions preserve the literal identifier, including `total`; natural-language aliases apply only within newly supported paraphrase productions. Unqualified reported fields retain the original root-or-summary ambiguity check.

Any syntactic identifier after `The reported` remains literal across operator variants and terminal punctuation. Multiword field aliases still map to their documented identifiers; `summary total` retains its explicit domain alias and summary path.
